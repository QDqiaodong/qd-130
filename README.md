# 大型超市母婴室配套设备区域调配单据打印系统

## 项目简介

本系统用于商超运营管理母婴室温奶器、婴儿护理台等配套设备，支持跨区域调配登记、日期区间筛选和调配单据打印存档。

系统包含设备巡检与故障处理模块：可按设备或区域维护巡检计划和周期（每日/每周/每月），登记巡检结果、异常描述、照片地址与备注；异常巡检经值班复核属实后可一键转报修单，跟踪待处理、维修中、已恢复状态流转；维修期间设备不可调配，恢复后才可重新调配；巡检列表支持日期、区域、巡检结果、维修状态筛选，详情页展示巡检与维修完整时间线，并校验重复提交与非法状态流转。

系统新增异常巡检值班复核模块：值班人员对已标异常的巡检补做复核，填写复核人、复核时间与是否属实；复核属实才允许转报修，复核不属实必须填写说明且该记录不能再报修；巡检列表可按巡检日区间和母婴室（含下级区域）过滤，并可叠加复核状态（待复核/属实/不属实）筛选，打开详情可核对复核人、复核时间与复核结论，处理时间线同步记录复核事件；漏填复核人/复核时间/复核结论、不属实漏填说明、重复复核以及接口请求失败均有明确提示；复核结论与可否报修由服务端统一落库计算，筛选条件保存在本地，刷新后复核结论和可否报修仍然对齐。

系统新增设备健康分析看板：支持按日期范围（默认近30天）和区域（含下级区域）汇总设备总数、当前维修数、巡检完成率（实际巡检数/按启用计划周期折算的计划巡检数）、异常率、待处理报修数和调配次数，并提供区域排行与设备类型排行；点击任意统计数字可下钻到对应的巡检、报修或调配明细（当前维修数、待处理报修数为当前状态指标，不带周期条件，保证明细数与卡片一致）；空数据、非法日期、区域不存在和接口失败均有明确提示，看板筛选条件保存在本地，刷新后指标口径保持一致。

报修模块支持超时催办：按区域（含下级区域，报修单记录区域口径）和约定等待小时数统计仍停在待处理的超时报修件数；点击件数进入催办清单，清单仅展示已超时的待处理单，可修改跟进人并留下催办说明（催办不改变报修单状态，说明与时间记入报修单详情时间线）；修改小时数或区域后需重新统计；没有超时单、小时数填写错误或接口请求失败均有明确提示；催办件数与清单行数来自同一统计结果，刷新后保持一致。

系统新增温奶器温度抽检模块：值班人员按母婴室区域对在用温奶器登记实测水温、抽检照片与抽检人，合格水温区间统一为40.0~50.0℃，抽检结论由服务端按温度自动判定落库（前端只做即时提示）；不合格记录醒目标红并提示补报修，可在列表或详情中一键创建报修单，已创建报修单的记录展示待处理/维修中/已恢复状态，不允许重复报修；抽检列表支持按抽检日期区间和母婴室区域（含下级）过滤，并可叠加结论与报修状态过滤，点开单条详情可查看抽检人、实测温度、照片、不合格说明与报修处理时间线；漏填温度/抽检人/日期、温度超出0~100℃物理范围、非温奶器或停用设备、同一台温奶器当日重复抽检以及接口失败均有明确提示；筛选条件保存在本地，刷新后抽检结论、不合格标记和报修入口与服务端数据保持一致。

系统新增调配到货签收模块：值班人员对已发出的调配单做到货签收，填写签收人、到货时间和外观是否完好；外观有破损时必须写清破损部位才能确认签收（破损部位由服务端强制校验落库，破损结论与部位在列表和详情中可核对）；未签收前该设备存在在途签收单，目标区域不能再把这台设备调走（调出闸门由服务端统一判定落库，登记调配时拦截并提示），签收完成后方可再次调出；签收台账可按调配日区间和目标区域（选父区域含全部下级）筛选，并可叠加外观筛选（待签收/外观完好/外观有破损，待签收即尚未填写外观结论的未签收单，筛选口径以服务端落库为准），列表展示签收状态、签收人、到货时间、外观结论与破损部位；筛选条件保存在本地，关掉页面再打开仍停在原筛选；点开单条详情可核对签收人、完好结论与破损部位；没有单子、漏填签收人/到货时间/外观结论、有破损未写破损部位、到货时间早于调配日期、对已取消单签收、重复签收、非法筛选条件以及接口超时/请求失败均有明确提示；刷新后签收标记与设备还能不能调出与服务端数据保持同一口径。

系统新增母婴室消毒登记模块：值班人员按母婴室登记当日消毒，填写消毒人、完成时间、消毒液和通风是否做完；通风没做完不能算当日闭环（闭环标记由服务端统一判定落库），通风未做完必须填写未完成原因，当日可再次登记补齐；同一母婴室当天不能重复闭环，已闭环后当日不可再登记（服务端拦截并落库唯一约束兜底）；登记列表可按消毒日区间和母婴室区域（含下级区域）筛选，并可叠加闭环状态过滤，列表展示闭环标记、未完成原因和能否再登记；漏填消毒人/完成时间/消毒液/通风结论、通风未做完漏填未完成原因、重复闭环以及接口请求失败均有明确提示；筛选条件保存在本地，刷新后闭环标记、未完成原因和能否再登记与服务端数据保持同一口径。

报修模块新增复用前试机门禁：维修完成点「确认恢复（结单）」前必须填写复用前试机结论（服务端强制校验落库，未试机不能结单，结论超500字亦拦截），恢复时同步记录试机时间并写入报修单处理时间线；报修列表新增「复用前试机」列与已试机/未试机筛选，是否已试机由服务端按落库试机结论统一计算（空结论视为未试机），筛选条件保存在本地，刷新后试机标记与筛选结果仍与服务端一致；详情页可核对试机结论与试机时间，维修中单据提示尚未试机；空结果、漏填试机结论、日期区间非法、接口请求失败/超时均有明确提示与重试入口。

系统新增值班交接用品盘点模块：值班交班前须按母婴室盘点湿巾和纸尿裤两类件数并登记交班单，交班人、接班人和两类件数均为必填（件数须为不小于0的整数，服务端强制校验落库）；登记后交接单为「未交接」，接班人核对件数后确认交接才算交出班，交接时间与交接状态由服务端统一落库，重复确认会被拦截并提示；交接清单可按母婴室（选父区域含全部下级在用母婴室）和是否已交接（未交接/已交接）筛选，筛选条件保存在本地，关掉页面再打开仍停在原筛选；没写接班人或件数、没有单子、区域不存在或已停用以及接口请求失败均有明确提示，清单加载失败可重试。

系统新增夜间巡更打卡模块：值班员按母婴室对前夜班（22:00-02:00）、后夜班（02:00-06:00）分别打卡，母婴室、巡更日期、班次、巡更人、打卡时间均为必填（服务端强制校验落库）；同一母婴室同一巡更日期同一班次只允许打一次卡，已打卡的房间不能再补同一班次（服务端拦截并由数据库唯一约束兜底）；巡更看板按巡更日期、班次和母婴室（选父区域含全部下级在用母婴室）筛选，漏打的房间按班次单独列在看板下方（班次选「全部」时前后夜班分别列出），可从漏打行直接补打卡；打卡记录与漏打房间来自同一统计口径，没有打卡记录、班次全部打卡无漏打、区域不存在以及接口请求失败均有明确提示，看板加载失败可重试；筛选条件保存在本地，关掉页面再打开仍停在原班次。

## 技术栈

- 前端：Vue 3、Vite、Axios
- 后端：Spring Boot 3.3、JDK 17、Spring Data JPA、Redis
- 数据库：MySQL 8.0
- 部署：Docker Compose

## Docker 构建说明

Docker Compose 使用固定端口并绑定 `127.0.0.1`；后端容器端口由 `SERVER_PORT=${BACKEND_PORT}` 注入，前后端镜像构建保留依赖缓存层。

## 常见问题

- 后端编译失败时先执行 `mvn -version` 检查 JDK，再检查 Lombok、Maven 编译插件和 `pom.xml` 是否被忽略。
- 前端构建失败时优先按实际报错检查 import 路径、导出名、Vite 代理端口和构建期语法。
- 页面中文乱码时检查源码、SQL 初始化脚本、数据库字符集、连接串编码和已有 Docker volume 数据；初始化 SQL 已增加 `SET NAMES utf8mb4;`。
